# 用户引导

只在首次使用、账号定位缺失或用户意图不完整时读取。本文件负责让用户知道“现在可以做什么”，不替代实际任务的输出结构。

## 简短过程提示

每个真实执行阶段最多一行。例如：

- `正在配置本机数据读取能力。`
- `正在等待扫码登录；登录后会自动继续。`
- `正在抓取并整理本轮公开笔记。`

不要展示内部推理、文件路径、命令、Cookie、API Key、浏览器端口或冗长步骤列表。用户明确要求技术诊断时才补充必要细节。

## 首次且意图不完整

账号定位、Apify Key 都不是开始使用的前置条件。只给以下简短入口，并允许用户直接用自然语言继续：

```text
你现在可以：
1. 找选题：告诉我领域或地区
2. 做调研：给我一个关键词
3. 仿写参考笔记：发一篇笔记链接
4. 根据对标账号做定位：发博主主页链接
```

用户已经明确说调研、仿写、对比、抓博主或生图时，直接执行，不重复展示入口。

## 无配置时的数据任务

当任务需要抓取而 Apify 未配置、Media 未安装时：自动进行 Media 初始化。先告诉用户“正在配置本机数据读取能力”。安装完成后先后台检查登录态；如需扫码，Codex 直接打开 MediaCrawler 原生小窗，并提示“登录窗口已打开，请扫码登录；扫码后我会自动继续。”随后自动做低频连接验证并继续原任务。系统权限弹窗和扫码确认是唯一需要用户操作的步骤；不要让用户自行复制 Terminal 命令。

## 对标账号与定位

用户提供博主主页，并表达“对标、参考、定位、规划、起号”等意图时，使用 Research 的作者抓取模式。先返回完整来源样本，再追加内容画像、账号定位草案和首批选题。

定位草案默认不写入 `profile/account.yaml`。只有用户明确回复“确认这个定位”或等价指令时，才保存为本地账号配置。

## 结果后的下一步

结果完成后最多给 3 条与本轮结果直接相连的建议：

- 调研后：提炼选题、做多对象对比、指定单篇仿写。
- 对标账号后：确认定位、扩大样本、按某个选题调研。
- 仿写后：轻度仿写、深度仿写、根据正文生图。
- Compare 后：扩大搜索（仅样本不足时）、换一个比较角度、根据正文生图。

不要每次罗列所有功能，也不要把下一步建议做成阻断用户继续对话的问卷。
