# 生图规划输出结构

本文件定义 Creator OS → xhs-image 的用户可见规划格式。它比仓库内置 `third_party/baoyu-xhs-images` 的完整 outline 更轻，只保留用户需要确认的内容。

## 阶段一：正文分析与封面确认

第一段沿用 Baoyu 的 Smart Confirm 信息结构：

```text
📋 内容分析
  主题：[主题]
  类型：[主题类型]
  要点：[1-3 个核心要点]
  受众：[目标受众]

🎨 推荐方案
  策略：[A / B / C 或简短策略名]
  风格：[视觉风格]
  布局：[系列层面的布局倾向]
  配色：[配色或默认]
  图片：[总张数]

🖼️ 封面确认
  标题候选：
  1. [标题候选]
  2. [标题候选]
  3. [标题候选]
  参考表情：[表情名称]｜[准确的参考文件名]
  大致内容：[一句话说明封面要表达什么]
```

规则：

- 标题候选只列候选，不写“推荐标题”和推荐理由。
- 不输出封面视觉长方案，不写封面限制、场景、排版、道具或完整卡片文字。
- 用户选择标题后，才把选中的标题写入封面 Prompt。
- 规划阶段不生成知识卡 Prompt，也不提前给出知识卡的具体文字、场景、排版或表情理由。
- 默认路径输出完这段内容后必须停止，等待用户选择标题或确认方案；写入 `analysis.md`、`outline.md` 不代表用户已经确认。
- 只有当前用户消息明确表达“直接生成一套”“不用确认”“跳过规划”等意思时，才可以跳过等待；必须记录触发直接模式的原文和实际采用的标题。
- 无法判断是否跳过确认时，按默认路径处理，不自行放行。

## 阶段二：封面生成与独立审查

```text
🎨 封面第 1 版
  [展示生成的封面图]

🔎 独立审查中
  审查范围：可见角色的生理结构、重复/缺失部位、肢体连接
  审查上下文：独立审查 Agent

✅ PASS
  [通过原因]
```

如果不通过：

```text
❌ 封面第 1 版未通过
  问题：[具体问题，例如单个角色多出一只爪子、耳朵重复、肢体发生粘连]
  修复方向：[下一版 Prompt 要怎么改]
  当前尝试：1/3

🔁 正在重新生成封面第 2 版
```

也允许返回：

```text
🟡 PASS_WITH_NOTE
  [轻微问题，但不影响使用；不返工]
```

只有明确影响使用的硬伤才判定 FAIL。最多 3 次；第 3 次仍不通过时，停止生成并输出失败原因；不能把未通过封面作为系列锚点。

## 阶段三：封面通过后的知识卡摘要

封面 PASS 后，才展示知识卡生成方案。每张卡只保留以下字段：

```text
📚 知识卡生成方案
  第 2 张｜参考表情：[表情名称]｜[准确的参考文件名]
  核心信息：[一句话总结这张图展示什么]

  第 3 张｜参考表情：[表情名称]｜[准确的参考文件名]
  核心信息：[一句话总结这张图展示什么]
```

不输出：卡片文字、场景、排版、道具、表情使用理由或封面式的长视觉方案。用户确认或处于直接生成模式后，才批量生成知识卡。

## 阶段四：知识卡批量生成与逐张审查

```text
📦 知识卡已生成，正在工作区展示
  [展示全部知识卡缩略图或文件]

🔎 正在逐张独立审查
  第 2 张：PASS
  第 3 张：未通过｜问题：[具体问题]｜重做次数：1/3
  第 4 张：PASS
```

每张卡单独判断、单独返工；一张卡失败不重做已经通过的卡。每张最多 3 次，最终仍失败则保留失败样本、最后一次 Prompt 和失败原因，并停止把该卡标记为通过。
