# 小红书生图流程

本文件只在用户明确提出“生图”“图片卡片”“小红书配图”或“审图”时加载。

## 执行清单

1. 读取仓库内置的 `third_party/baoyu-xhs-images/SKILL.md`，使用其图片生成规则；若项目级 `.baoyu-skills/baoyu-xhs-images/EXTEND.md` 存在，再将其作为可选偏好覆盖。
2. 每张图片先保存完整 Prompt，再调用图片生成后端；但在封面通过前，只允许保存封面 Prompt。
3. 封面先生成；生成后立刻把第一版成图展示给用户，并把同一文件交给独立审查上下文。审查结果必须明确输出 `PASS`、`PASS_WITH_NOTE` 或 `FAIL`。
4. 封面只有在独立审查 `PASS` 或 `PASS_WITH_NOTE` 后才能进入知识卡规划和生成；后续卡片使用通过的封面作为系列锚点。
5. 如果主题属于狗狗账号 IP，读取 `ip-routing.md`。
6. 每张候选图都读取 `anatomy-review-agent.md`，逐张交给独立审图上下文；这不是 Baoyu 自检，也不因用户没有说“审图”而跳过。
7. 失败只重新生成对应卡片，保留失败样本和修复 Prompt；每张图最多 3 次。第 3 次仍失败时停止该图并输出失败原因。
8. 知识卡全部生成后先在工作区展示，再逐张审查；不要因为其中一张失败而重做已经 PASS 的卡片。
9. 每次生成前检查 `run-state.yaml`；若封面状态不是 `passed`，禁止创建或调用第 2 张及之后的 Prompt。

## 边界

- 生图不会被调研、仿写或 Compare 自动触发。
- 狗狗 IP 素材只在相关主题和生图请求同时成立时加载。
- 独立审图只判断可见角色的生理结构，不判断文字、排版、遮挡、场景、IP 是否同一只狗、审美、文案事实或政策内容。

## 用户可见的进度输出

每次生成和审查都要按以下顺序输出，不得只在后台完成：

1. `封面第 N 版`：展示实际成图。
2. `独立审查中`：说明正在检查可见角色的生理结构，明确这是独立审查 Agent。
3. `PASS` 或 `PASS_WITH_NOTE`：说明可以进入下一阶段；或 `FAIL`：陈述具体问题、修复方向和 `当前尝试 N/3`。
4. 封面通过后，展示精简的知识卡摘要方案；知识卡批量完成后展示全部成图，再输出逐张审查结果。
